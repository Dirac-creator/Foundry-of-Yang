# 总体架构

初期使用单仓库、模块化 Python 包。v0.2.0 增加 FastAPI 网页表单和服务端 SQLite，用于本机及小团队集中录入验证，详见 shared-database.md。

```text
设备文件 / 实验录入
        ↓
data：导入与格式、单位、关联校验
        ↓
统一数据集（样品、工艺执行、测量、版图和文件引用）
        ↓
processes：退火 / 镀膜 / 刻蚀模型
        ↓
workflows：工艺链编排 → optical：光学测试分析
        ↓
未来：可视化、参数建议和新版本模型校准
```

## 边界

- `data`：负责数据可读性与一致性，不推断缺失单位或实验条件。
- `processes`：每种工艺独立实现，共享输入输出约定。
- `workflows`：传递工艺前后状态，不将实验事实等同于模型预测。
- `optical`：按器件和测试条件关联结果，不仅按文件名匹配。
- Schema 当前描述交换文件；未来数据库实现必须保留这些语义。

记录工艺与测量不依赖仿真成功。原始文件与结构化元数据分开保存。真实文件由实验室统一存储，JSON 保存 URI 和 SHA-256；本版不访问 URI、不验证文件内容校验和。

数据校验工具和 service 录入服务可运行。工艺模型、流程编排和光学分析包仍为接口开发预留。不连接设备，也不自动执行工艺。

## v0.4.0 GitHub模式

新增纯浏览器 GitHub API 适配器，可由 Pages 托管，不依赖本机后端。通过Git树、提交和非强制引用更新将数据保存为独立文件，同时维护查询索引。身份来自个人GitHub令牌，详见 [GitHub存储说明](github-storage.md)。本机模式继续使用SQLite。
